# nim-nucleus API Guide

This guide explains how to use `nim-nucleus` from application code.

For a function-by-function reference, use the documentation generated by
`nimble doc`. This guide focuses on the practical flow: initialize BLE,
scan advertising reports, optionally connect to a peripheral, use GATT,
receive notifications, persist bonding keys, and shut down cleanly.

## 1. Overview

`nim-nucleus` is a Nim wrapper for the NetNucleus BLE stack. It is intended
for embedded Linux systems that use NetNucleus instead of BlueZ.

The usual runtime model is:

```text
Application
  -> BleNim / Gatt
    -> BleClient
      -> btmd
        -> NetNucleus libBTM.so
```

Application code should normally use the high-level API:

- `BleNim` for BLE stack initialization, scanning, device discovery,
  white-list management, bonding-key management, and connecting to peripherals.
- `Gatt` for GATT operations after a connection is established.

`BleClient` and `GattClient` are lower-level building blocks. They are useful
for internal implementation, debugging, or protocol-level experiments, but most
applications should not need to use them directly.

## 2. API layers

| Layer | Main types | Intended users |
|---|---|---|
| High-level API | `BleNim`, `Gatt`, `BleDevice` | Normal Nim applications |
| Internal BLE client | `BleClient`, `GattClient` | Library internals and low-level tests |
| Bridge daemon | `btmd` | Target-device integration |
| BLE runtime | NetNucleus `libBTM.so` | Vendor stack |

The repository may contain development or test code that talks to `BleClient`
directly. Treat that as low-level sample code. New application code should start
from `BleNim`.

## 3. Runtime model

`btmd` is a bridge daemon that runs on the target device where the NetNucleus
runtime is available. It talks to the NetNucleus C API and exposes a framed
socket protocol to Nim applications.

Applications connect to `btmd` either through a Unix domain socket or through a
TCP socket.

```nim
let ble = newBleNim(path = "/tmp/btmd.sock")
```

or:

```nim
let ble = newBleNim(host = "127.0.0.1", port = 9876)
```

Normally, application developers do not run `btmd` on a development PC unless
that PC also has the NetNucleus runtime installed.

## 4. Basic lifecycle

A typical application follows this flow:

```text
create BleNim
initialize BLE
start scanning
wait for advertising reports
optionally connect to selected devices
use GATT
stop scanning / disconnect
close BleNim
```

Minimal structure:

```nim
import std/asyncdispatch
import results
import nim_nucleus

proc main() {.async.} =
  let ble = newBleNim()
  if not await ble.init():
    echo "BLE initialization failed"
    return

  try:
    discard await ble.startStopScan(active = true, enable = true)

    let devRes = await ble.waitDevice(timeout = 10_000)
    if devRes.isErr:
      echo "no device found"
      return

    let dev = devRes.get()
    echo dev
  finally:
    discard await ble.startStopScan(active = true, enable = false)
    ble.close()

waitFor main()
```

`newBleNim(initialize = true)` is also available when an application wants to
initialize the stack during object construction:

```nim
let ble = newBleNim(initialize = true)
```

For larger applications, explicit `init()` is usually easier to handle because
it gives the caller a clear success/failure point.

## 5. Scanning and advertising reports

Use `startStopScan()` to enable or disable scanning.

```nim
discard await ble.startStopScan(
  active = true,
  enable = true,
  filterDuplicates = true,
  filterPolicy = ScanFilterPolicy.AcceptAllExceptDirected
)
```

Important arguments:

| Argument | Meaning |
|---|---|
| `active` | `true` for active scan, `false` for passive scan |
| `enable` | `true` to start scanning, `false` to stop scanning |
| `scanInterval` | Scan interval in 0.625 ms units; `0` keeps or uses the default |
| `scanWindow` | Scan window in 0.625 ms units; `0` keeps or uses the default |
| `filterDuplicates` | Enable duplicate filtering in the controller/stack |
| `filterPolicy` | Advertising filter policy |

`waitDevice()` waits for an advertising report converted into a `BleDevice`.

```nim
let devRes = await ble.waitDevice(timeout = 5_000)
if devRes.isOk:
  let dev = devRes.get()
  echo dev.peerAddrStr
  echo dev.rssi
```

`timeout` is in milliseconds. `timeout = 0` means wait indefinitely.

A `BleDevice` contains fields commonly needed by applications:

| Field | Meaning |
|---|---|
| `peer` | BLE peer address and address type |
| `peerAddrStr` | Bluetooth address string such as `AA:BB:CC:DD:EE:FF` |
| `name` | Optional device name from advertising data |
| `rssi` | RSSI in dBm |
| `advertiseData` | Raw advertising payload used by the parser |
| `manufacturerData` | Optional manufacturer-specific data |
| `seenTime` | Time when the report was received |

Previously discovered devices can be inspected with:

```nim
let devices = ble.allDevices()
let byName = ble.findDeviceByName("MyDevice")
let byAddr = ble.findDeviceByAddr("AA:BB:CC:DD:EE:FF")
```

## 6. Advertising-only applications

Many BLE devices are useful without GATT. Sensors, beacons, and simple devices
may expose all required information in advertising packets and scan responses.

For these applications, a common pattern is:

1. Start active or passive scanning.
2. Repeatedly call `waitDevice()` for a fixed time.
3. Parse `manufacturerData`, service UUIDs, names, or other advertising data.
4. Keep a table keyed by `peerAddrStr`.
5. Merge multiple reports from the same peer address.

Example skeleton:

```nim
import std/asyncdispatch
import std/options
import std/tables
import std/times
import nim_nucleus

type
  FoundDevice = object
    address: string
    name: Option[string]
    rssi: int8

proc collectAdvertising(ble: BleNim, durationSec: int): Future[Table[string, FoundDevice]] {.async.} =
  var devices: Table[string, FoundDevice]
  let endTime = now().toTime.toUnixFloat() + durationSec.float

  while true:
    let waitMs = int((endTime - now().toTime.toUnixFloat()) * 1000.0)
    if waitMs <= 0:
      break

    let devRes = await ble.waitDevice(timeout = waitMs)
    if devRes.isErr:
      break

    let dev = devRes.get()
    devices[dev.peerAddrStr] = FoundDevice(
      address: dev.peerAddrStr,
      name: dev.name,
      rssi: dev.rssi
    )

  result = devices
```

Advertising-only applications should not assume that all information is present
in a single report. Some devices put manufacturer data in the advertising
packet and device type or service information in the scan response. In that
case, keep partial state keyed by address and update it as reports arrive.

A SwitchBot-like parser may follow this style:

```nim
if dev.manufacturerData.isSome:
  let manData = dev.manufacturerData.get()
  if manData.len >= 2:
    let companyId = manData.getLe16(0)
    if companyId == 0x0969'u16:
      echo "SwitchBot-family device candidate: ", dev.peerAddrStr
```

Then a later scan response from the same address can be used to refine the
device type.

## 7. Connecting after discovery

Use `connect()` to establish a GATT connection.

```nim
let gattRes = await ble.connect(dev, timeout = 10_000)
if gattRes.isErr:
  echo "connect failed: ", gattRes.error
  return

let gatt = gattRes.get()
```

You can also connect by address:

```nim
let gattRes = await ble.connect("AA:BB:CC:DD:EE:FF", random = false)
```

When scanning is active, `connect()` stops scanning before connecting because
some NetNucleus/controller combinations do not support every combination of
central connection initiation and scanning. If `autoRescan = true`, scanning is
restarted after a successful connection.

```nim
let gattRes = await ble.connect(dev, autoRescan = true, timeout = 10_000)
```

For applications that discover many devices and then connect only to selected
ones, it is often useful to run each GATT connection in a separate async task.

```nim
proc handleGatt(gatt: Gatt) {.async.} =
  try:
    let nameRes = await gatt.readGattChar(CharaUuid.DeviceName)
    if nameRes.isOk:
      echo nameRes.get().value.toString()
  finally:
    await gatt.disconnect()

let gattRes = await ble.connect(dev, timeout = 10_000)
if gattRes.isOk:
  asyncCheck handleGatt(gattRes.get())
  discard await ble.restartScan()
```

## 8. GATT basics

After `connect()` succeeds, the returned `Gatt` object provides high-level GATT
operations.

### Read a characteristic by UUID

```nim
let nameRes = await gatt.readGattChar(CharaUuid.DeviceName)
if nameRes.isOk:
  let hv = nameRes.get()
  echo hv.value.toString()
```

You can also pass a UUID string:

```nim
let battRes = await gatt.readGattChar("2a19")
```

### Read a characteristic by handle

```nim
let valueRes = await gatt.readGattChar(0x0021'u16)
if valueRes.isOk:
  let bytes = valueRes.get()
```

### Write a characteristic by handle

```nim
discard await gatt.writeGattChar(0x0024'u16, @[0x01'u8])
```

For write without response:

```nim
discard await gatt.writeGattChar(0x0024'u16, @[0x01'u8], withResponse = false)
```

### Read and write descriptors

```nim
let descRes = await gatt.readGattDescriptor(0x0022'u16)
discard await gatt.writeGattDescriptor(0x0022'u16, 0x0001'u16)
```

For CCCD operations, prefer the `CCC` enum where possible:

```nim
discard await gatt.writeGattDescriptor(0x0022'u16, CCC.Notify)
```

## 9. Notifications and CCCD

BLE notifications and indications are normally enabled by writing the Client
Characteristic Configuration Descriptor, usually called CCCD.

Common values:

| Value | `CCC` enum | Meaning |
|---:|---|---|
| `0x0000` | `CCC.Disable` | Disable notification/indication |
| `0x0001` | `CCC.Notify` | Enable notification |
| `0x0002` | `CCC.Indicate` | Enable indication |

Example:

```nim
const valueHandle = 0x0021'u16
const cccdHandle = 0x0022'u16

discard await gatt.writeGattDescriptor(cccdHandle, CCC.Notify)

try:
  while gatt.isConnected():
    let notifyRes = await gatt.waitNotification(timeout = 10_000)
    if notifyRes.isErr:
      break

    let hv = notifyRes.get()
    if hv.handle == valueHandle:
      echo hv.value
finally:
  discard await gatt.writeGattDescriptor(cccdHandle, CCC.Disable)
```

For real devices, the value handle and CCCD handle are normally discovered from
the service/characteristic layout or taken from the device specification.

## 10. Bonding keys

Some peripherals require pairing/bonding. For central-mode applications, the
remote device keys must be persisted by the application if the device should be
reused after reboot.

The main type is `RemoteCollectionKeys`.

Common flow:

1. At startup, load stored keys from disk.
2. Call `setAllRemoteCollectionKeys()` before connecting.
3. Pair/connect/use the peripheral.
4. After pairing has completed, call `getAllRemoteCollectionKeys()`.
5. Save the returned keys to disk.

Restore keys at startup:

```nim
import std/json

let jsonNode = parseFile("bonded-keys.json")
discard await ble.setAllRemoteCollectionKeys(jsonNode)
```

Save keys:

```nim
let keys = ble.getAllRemoteCollectionKeys()
writeFile("bonded-keys.json", $(%keys))
```

Remove keys for one peripheral:

```nim
discard await ble.removeRemoteCollectionKeys(peer)
```

Remove all stored keys:

```nim
discard await ble.removeAllRemoteCollectionKeys()
```

When a device initiates encryption or pairing immediately after connection,
use `waitEncryptionComplete()` before performing GATT operations that require
encryption.

```nim
let encRes = await gatt.waitEncryptionComplete()
if encRes.isErr:
  echo "encryption did not complete: ", encRes.error
```

## 11. White-list management

The wrapper exposes the controller/stack white list through `BleNim`.

```nim
let size = await ble.getWhiteListSize()
discard await ble.clearWhiteList()
discard await ble.addDeviceToWhiteList("AA:BB:CC:DD:EE:FF")
discard await ble.removeDeviceFromWhiteList("AA:BB:CC:DD:EE:FF")
```

The current in-memory white-list entries can be iterated with:

```nim
for peer in ble.devicesInWhiteList():
  echo peer
```

Use `ScanFilterPolicy.WhitelistOnly` if scanning should accept only white-listed
devices.

## 12. Error handling

Most high-level asynchronous GATT operations return `Future[Result[T,
ErrorCode]]`. Check `isOk` / `isErr` before using the value.

```nim
let res = await gatt.readGattChar(CharaUuid.DeviceName)
if res.isErr:
  case res.error
  of ErrorCode.Timeouted:
    echo "timeout"
  of ErrorCode.Disconnected:
    echo "disconnected"
  else:
    echo "GATT read failed: ", res.error
  return

let value = res.get()
```

Typical meanings:

| ErrorCode | Typical meaning | Common handling |
|---|---|---|
| `Timeouted` | Expected response/event did not arrive in time | Retry or reconnect |
| `Disconnected` | Peripheral or `btmd` connection was lost | Reconnect |
| `OpcMismatch` | Unexpected opcode was received | Treat as protocol-state error; reconnect |
| `GattError` | GATT-level failure | Check target handle/UUID and device state |
| `ParseError` | Packet parsing failed | Log and reconnect if needed |
| `ValueError` | Invalid argument or invalid state | Fix caller input or state handling |
| `DeviceNotFound` | Requested device was not found | Continue scanning or check filters |

Some GAP/setup APIs return `bool` rather than `Result`. Treat `false` as a
failed operation and log enough context in the application.

## 13. Concurrency model

`nim-nucleus` is based on `asyncdispatch`.

Typical concurrent activities are:

- an advertising receive loop using `waitDevice()`;
- one or more GATT tasks created after selected devices are discovered;
- notification receive loops using `waitNotification()`;
- background handlers inside `BleNim` and `BleClient`.

Recommended practices:

- Use one task per active GATT connection.
- Disconnect a `Gatt` object when the task is finished.
- Disable CCCD before disconnecting if the device expects explicit cleanup.
- Restart scanning after connection if the application should keep discovering
  devices.
- Call `BleNim.close()` during application shutdown.

## 14. Low-level API notes

`BleClient` and `GattClient` are exported through the internal package modules,
but they should be considered lower-level APIs. They expose operations closer to
NetNucleus commands and events.

The old development `app.nim` style is useful for understanding the underlying
command flow:

| Low-level style | High-level style |
|---|---|
| `newBleClient()` | `newBleNim()` |
| `initBTM()` | `BleNim.init()` |
| `setScanParametersReq()` + `setScanEnableReq()` | `startStopScan()` |
| manual advertising handling | `waitDevice()`, `allDevices()` |
| `gattConnect()` | `BleNim.connect()` |
| `GattClient.gattReadCharacteristicValue()` | `Gatt.readGattChar(handle)` |
| `GattClient.gattReadUsingCharacteristicUuid()` | `Gatt.readGattChar(uuid)` |
| `GattClient.gattWriteCharacteristicDescriptors()` | `Gatt.writeGattDescriptor()` |
| `GattClient.waitNotify()` | `Gatt.waitNotification()` |

New application code should normally use the high-level API unless it needs to
validate or debug the NetNucleus protocol itself.

## 15. Practical examples

### Advertising collector

```nim
proc scanForSeconds(ble: BleNim, seconds: int) {.async.} =
  discard await ble.startStopScan(active = true, enable = true)
  defer:
    asyncCheck ble.startStopScan(active = true, enable = false)

  let endTime = now().toTime.toUnixFloat() + seconds.float
  while true:
    let waitMs = int((endTime - now().toTime.toUnixFloat()) * 1000.0)
    if waitMs <= 0:
      break

    let devRes = await ble.waitDevice(timeout = waitMs)
    if devRes.isErr:
      break

    let dev = devRes.get()
    echo dev.peerAddrStr, " RSSI=", dev.rssi
```

### Read Device Name after discovery

```nim
let devRes = await ble.waitDevice(timeout = 10_000)
if devRes.isOk:
  let gattRes = await ble.connect(devRes.get(), timeout = 10_000)
  if gattRes.isOk:
    let gatt = gattRes.get()
    try:
      let nameRes = await gatt.readGattChar(CharaUuid.DeviceName)
      if nameRes.isOk:
        echo nameRes.get().value.toString()
    finally:
      await gatt.disconnect()
```

### Enable notifications

```nim
const valueHandle = 0x0021'u16
const cccdHandle = 0x0022'u16

discard await gatt.writeGattDescriptor(cccdHandle, CCC.Notify)
let notifyRes = await gatt.waitNotification(timeout = 5_000)
if notifyRes.isOk:
  let hv = notifyRes.get()
  echo "handle=", hv.handle, " value=", hv.value
discard await gatt.writeGattDescriptor(cccdHandle, CCC.Disable)
```
